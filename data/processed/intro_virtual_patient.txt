# Virtual Patient Systems — 虛擬病人系統

## 什麼是虛擬病人？

虛擬病人（Virtual Patient, VP）是一種電腦模擬的病人角色，用於醫學教育與臨床技能訓練。學習者（醫學生、護理師、醫療從業人員）可以與虛擬病人進行問診對話、做出診斷判斷，在安全的模擬環境中練習臨床技能，而無需直接接觸真實病患。

## 虛擬病人 vs 標準化病人

| 面向 | 標準化病人（Standardized Patient, SP）| 虛擬病人（Virtual Patient, VP）|
|---|---|---|
| 定義 | 由真人演員扮演病人角色 | 電腦程式模擬病人 |
| 可及性 | 需要排程、場地、人員 | 隨時隨地可使用 |
| 規模化 | 困難（一次只能一對一）| 容易（多個學生同時使用）|
| 一致性 | 演員表現可能有差異 | 每次互動一致 |
| 即時回饋 | 需要評估者手動評分 | 可自動生成回饋 |
| 情緒表達 | 豐富自然 | 受技術限制 |
| 成本 | 高（人員酬勞、場地費）| 初期開發成本高，後續邊際成本低 |

## 虛擬病人在醫學教育的用途

### 1. 問診技能訓練（History Taking）
練習系統性地收集病史，包括主訴、現病史、過去病史、家族史、用藥史等。虛擬病人可以模擬各種病症，讓學生反覆練習問診流程。

### 2. 臨床推理訓練（Clinical Reasoning）
學生根據問診結果做出鑑別診斷，虛擬病人系統可以根據學生的決策提供不同的病情進展，訓練臨床思維。

### 3. 溝通技巧訓練（Communication Skills）
練習如何與不同情緒狀態的病人溝通，例如：焦慮的病人、否認病情的病人、配合度低的病人。

### 4. OSCE 準備
OSCE（Objective Structured Clinical Examination）是醫學生的重要考試，虛擬病人提供無限次的練習機會。

## LLM 驅動的現代虛擬病人

傳統虛擬病人系統使用預先設計的決策樹（decision tree），病人回應受限於固定劇本。現代系統整合大型語言模型（LLM），使虛擬病人能夠：

1. **自由對話**：回應學生的任意問題，不受固定腳本限制
2. **角色一致性**：在多輪對話中維持病人的病史、情緒、個性一致
3. **動態適應**：根據學生的問診方向調整回應深度與細節
4. **自動回饋**：評估學生的問診完整性並給予建議

## Cascade 語音虛擬病人的優勢

本系統採用語音介面（Voice-enabled VP），相較於純文字系統具備以下優勢：

1. **更真實的模擬**：真實問診是口語互動，語音介面更貼近實際臨床情境
2. **溝通技巧評估**：可以評估語音表達能力，而非只測試文字輸入能力
3. **情緒感知**：SER 模組偵測學生說話時的情緒，讓虛擬病人能夠給予更符合情境的回應
4. **沉浸感**：TTS 合成的病人聲音增強使用者的臨床場景代入感

## Persona 設計（病人角色設定）

一個好的虛擬病人 Persona 包含以下元素：

```
病人姓名：王小明
年齡：58 歲
性別：男
主訴：胸口悶痛 3 天
現病史：3 天前開始出現胸口悶痛，活動後加劇，休息後稍微緩解
過去病史：高血壓（控制中）、糖尿病（口服藥物）
家族史：父親有心肌梗塞病史
用藥史：amlodipine 5mg QD、metformin 500mg BID
情緒狀態：焦慮、擔心，不知道自己是不是心臟病
語言風格：台灣中文，偶爾夾雜台語，說話較慢
禁忌資訊：除非學生直接問，否則不主動提及過去有類似發作
```

## 常見評估指標

| 指標 | 說明 |
|---|---|
| **對話自然度** | 病人回應是否符合真實病人的說話方式 |
| **醫學正確性** | 病人描述的症狀與病史是否在醫學上一致 |
| **角色一致性** | 多輪對話中病人角色是否保持一致 |
| **回應延遲** | 從使用者說話到病人回應的時間（語音系統需低於 3 秒）|
| **學生學習成效** | 使用前後的 OSCE 成績或問診完整度提升 |

## 現有代表系統

| 系統 | 特色 |
|---|---|
| **CLiVR** | 結合 VR 頭盔，提供沉浸式臨床模擬體驗 |
| **PatientSim** | 使用 LLM 模擬複雜病人，支援多種病症 |
| **MEDSAGE** | 強調醫療知識的準確性，整合醫學知識圖譜 |
| **本系統** | Cascade 語音架構，整合 SER 情緒感知與 RAG 知識檢索 |

## 挑戰與限制

1. **幻覺問題（Hallucination）**：LLM 可能生成醫學上不正確的病人回應
2. **角色越界**：LLM 可能跳出病人角色，給出診斷建議（需要 prompt 設計防護）
3. **情緒連貫性**：多輪對話中維持一致的情緒弧線仍是挑戰
4. **評估困難**：虛擬病人回應的品質難以用單一指標量化
5. **文化適應性**：台灣醫療情境、中文醫療術語、本地病患溝通習慣的適配
