# Dialogue Generation for Virtual Patients — 虛擬病人對話生成

## 什麼是對話生成？

對話生成（Dialogue Generation）是讓 AI 系統根據對話歷史與情境，自動產生符合角色設定的回應文字的技術。在虛擬病人系統中，對話生成的目標是讓 LLM 扮演一位真實可信的病人角色，對醫學生的問診做出適切回應。

## 對話生成的核心挑戰

### 1. 角色一致性（Persona Consistency）
在多輪對話中，虛擬病人必須維持一致的病史、個性、情緒與說話風格。例如：
- 學生在第 3 輪問「你有沒有家族病史？」
- 病人不能給出與第 1 輪設定矛盾的答案

**解決方案**：在每次 LLM 呼叫的 system prompt 中附上完整的 Persona 設定，並傳入完整的對話歷史。

### 2. 醫療知識的正確性
病人描述症狀時，必須符合醫學邏輯。例如心肌梗塞病人描述的胸痛特徵（壓迫感、放射至左肩）必須與臨床表現一致。

**解決方案**：整合 RAG，從醫療知識庫中檢索相關資訊，作為 LLM 生成回應的根據。

### 3. 資訊釋出控制（Information Disclosure）
真實病人不會主動揭露所有資訊，只有在被問到時才說。虛擬病人也需要模擬這種「被動揭露」的行為。

**解決方案**：在 Persona 設定中明確標記哪些資訊是「主動說」vs「被問才說」。

### 4. 情緒一致性（Emotional Consistency）
病人的情緒狀態應該在整個對話過程中有合理的演變，並與 SER 偵測到的使用者情緒互動。

## Prompt Engineering for Dialogue Generation

### System Prompt 設計
```
你是一位正在急診室等待的 58 歲男性病人，名叫王小明。

[病人基本資料]
主訴：胸口悶痛 3 天
現病史：活動後加重，休息後稍緩
過去病史：高血壓、糖尿病
情緒：焦慮，擔心是心臟病

[行為規則]
- 只以病人的口吻回答，不要使用醫學專業術語
- 只有被問到才透露相關資訊，不主動揭露完整病史
- 描述症狀時用日常語言（「胸口很悶很重」而非「胸骨後壓迫性疼痛」）
- 如果學生問了不相關的問題，可以表示困惑或說不知道
- 適時表現焦慮情緒（「醫生，我是不是很嚴重啊？」）
```

### 情緒整合
將 SER 輸出整合進對話生成 Prompt：
```
[當前學生情緒狀態（由 SER 分析）]
情緒：緊張（confidence: 0.82）

請根據學生的情緒狀態調整你的回應風格：
- 若學生緊張，病人可以適當表現理解，放慢說話節奏
- 若學生冷靜，病人可以正常回應
```

## 多輪對話管理

### 對話歷史的傳遞
LLM 沒有跨次呼叫的記憶，每次呼叫必須傳入完整的對話歷史：

```python
messages = [

{"role": "system", "content": system_prompt},

{"role": "user", "content": "你哪裡不舒服？"},

# 第 1 輪使用者

{"role": "assistant", "content": "胸口很悶..."},

# 第 1 輪病人

{"role": "user", "content": "痛多久了？"},

# 第 2 輪使用者

{"role": "assistant", "content": "大概三天了..."}, # 第 2 輪病人

{"role": "user", "content": current_user_input}

# 本輪使用者輸入
]
```

### Context Window 管理
長對話可能超出 LLM 的 context window 限制，需要策略性地截斷或摘要早期對話。

## 合成醫療對話資料

### SynDial（arXiv: 2408.06285）
從臨床病歷（Clinical Notes）自動生成模擬的醫病對話。核心流程：
1. 輸入：病人的電子病歷（EMR）摘要
2. 使用 LLM 以 zero-shot prompting 生成醫病對話
3. 用相似度與資訊提取率（Extractiveness）評分，不達標則迭代生成直到通過
4. 輸出：高品質的合成醫病對話資料

### 合成資料的用途
- 訓練虛擬病人系統的對話品質評估模型
- Fine-tune LLM 使其更擅長扮演病人角色
- 建立 benchmark 評估不同虛擬病人系統的對話品質

## 角色扮演（Role-Playing）技術

### LLM Role-Playing 的基本原理
現代 LLM 在預訓練階段接觸過大量角色扮演相關文本，具備扮演特定角色的能力。透過精心設計的 prompt，LLM 可以：
- 維持角色的知識邊界（病人不知道自己的確切診斷）
- 模擬角色的說話風格與情緒反應
- 在角色設定的框架內自由回應未預見的問題

### 角色扮演的常見失敗模式
1. **角色越界（Role Break）**：LLM 忘記自己是病人，直接給出醫學建議
2. **過度詳細**：LLM 主動說出病人不應知道的診斷資訊
3. **情緒失真**：病人的情緒反應與角色設定不符
4. **資訊矛盾**：前後對話中病人給出矛盾的病史資訊

### 防護策略
- 在 prompt 中明確列出「不能做的事」
- 使用 temperature 控制（較低的 temperature 使回應更穩定一致）
- 對 LLM 輸出進行後處理過濾，偵測角色越界的回應

## 評估對話品質

| 評估維度 | 自動指標 | 人工評估 |
|---|---|---|
| 醫學正確性 | — | 由醫學專家評分 |
| 對話自然度 | BLEU、ROUGE（參考對話）| MOS 評分 |
| 角色一致性 | Persona Consistency Score | 人工評估前後矛盾 |
| 資訊完整性 | Extractiveness（資訊提取率）| 病史覆蓋率 |
| 學習成效 | 前後 OSCE 分數差異 | 教師主觀評估 |
