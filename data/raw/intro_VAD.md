# Voice Activity Detection (VAD) — 語音活動偵測

## 什麼是 VAD？

語音活動偵測（Voice Activity Detection, VAD）是一種自動判斷音訊流中「哪些片段包含人類語音」、「哪些片段是靜音或背景噪音」的技術。VAD 的輸出通常是一系列時間戳記，標記語音的起始與結束點。

VAD 本身不理解語音的內容，只負責回答一個二元問題：**「現在有人在說話嗎？」**

## VAD 在 Cascade Pipeline 中的角色

在 Cascade 語音虛擬病人系統中，VAD 是整個 Pipeline 的第一個模組，位於麥克風輸入之後、ASR 之前：

```
麥克風音訊流（連續輸入）
        ↓
  [VAD] 語音活動偵測
        ↓（只有偵測到語音才往下傳）
  [ASR] 自動語音辨識
        ↓
  [SER] 語音情緒辨識
        ↓
  [LLM + RAG] 對話生成
        ↓
  [TTS] 語音合成
```

**沒有 VAD 的問題：**
- ASR 會持續推論靜音片段，浪費大量計算資源
- 靜音段的 ASR 輸出（空字串或雜訊）會污染 LLM 的輸入
- 系統無法判斷使用者何時說完話，對話流程無法正常推進
- 整體系統延遲大幅增加

## VAD 的技術原理

### 傳統方法
早期 VAD 使用手工設計的聲學特徵（如能量閾值、過零率、短時能量）進行靜音偵測。這類方法計算成本低，但在背景噪音複雜的環境下容易誤判。

### 深度學習方法（當前主流）
現代 VAD 使用神經網路學習語音與非語音的聲學差異，對各種背景噪音（辦公室噪音、音樂、交通聲）具有強健的泛化能力。代表工具為 Silero VAD。

### WebRTC VAD
Google WebRTC 框架內建的 VAD，是傳統方法的代表，廣泛應用於網路通話系統。計算極快，但對複雜噪音環境的適應性較弱。

## 主要 VAD 工具比較

| 工具 | 方法 | 模型大小 | 語言相關性 | 適合情境 |
|---|---|---|---|---|
| **Silero VAD** | 深度學習（LSTM）| ~1MB | 語言無關 | 即時對話系統首選 |
| **WebRTC VAD** | 傳統聲學特徵 | 極小 | 語言無關 | 低資源嵌入式系統 |
| **pyannote.audio** | 深度學習 | 較大 | 語言無關 | 需要精確說話者分離 |
| **Whisper 內建 VAD** | 深度學習 | 隨 Whisper | 語言無關 | 離線批次處理 |

## Silero VAD：推薦工具

### 為什麼選 Silero VAD？

Silero VAD 是目前即時語音對話系統的業界首選，原因如下：

- **輕量**：模型大小僅約 1MB，推論速度極快（CPU 上約 1–2ms per chunk）
- **準確**：在多語言、多噪音環境下表現穩定，不受語言種類影響
- **串流支援**：可逐幀（512 samples）處理即時音訊，無需等待完整語句
- **免費開源**：MIT License，可用於商業與研究用途
- **易整合**：Python API 簡潔，`pip install silero-vad` 即可使用

### Silero VAD 的核心參數

| 參數 | 說明 | 建議值 |
|---|---|---|
| `threshold` | 語音信心度閾值（0~1）| 安靜環境 0.5，嘈雜環境 0.7 |
| `min_speech_duration_ms` | 最短語音片段（毫秒），過濾短暫噪音 | 250ms |
| `min_silence_duration_ms` | 靜音多久才判定說話結束 | 對話場景 300–500ms |
| `window_size_samples` | 每次分析的音訊窗口大小 | 512 samples（@ 16kHz）|

### 語音片段的識別流程

1. 麥克風持續錄製音訊，每 512 samples 為一個 chunk
2. Silero VAD 對每個 chunk 計算語音信心度（0~1 之間的浮點數）
3. 信心度超過 `threshold` → 判定為語音，開始累積音訊 buffer
4. 信心度低於 `threshold` 且持續超過 `min_silence_duration_ms` → 判定說話結束
5. 將累積的完整語音 buffer 送往 ASR 模組處理

## VAD 與 ASR 的串接設計

### 串流 VAD 的重要性

Faster Whisper 雖然內建 `vad_filter=True`，但這是**批次模式**，適合離線音訊處理。在需要即時回應的虛擬病人對話系統中，必須使用**串流 VAD** 來：

1. 即時偵測使用者開始說話的時間點（觸發錄音）
2. 即時偵測使用者說完話的時間點（觸發 ASR 推論）
3. 避免在使用者尚未說完時就送入 ASR（避免截斷）

### 延遲分析

在整個 Cascade Pipeline 中，各模組的延遲貢獻：

| 模組 | 典型延遲 | 說明 |
|---|---|---|
| **VAD** | 1–5ms | 幾乎不影響整體延遲 |
| **ASR（Faster Whisper small）** | 200–500ms | 主要延遲來源之一 |
| **SER（wav2vec2）** | 100–300ms | 可與 ASR 平行執行 |
| **LLM 生成** | 500ms–3s | 最主要延遲來源 |
| **TTS（VITS）** | 100–500ms | 視文字長度而定 |

從以上可見，VAD 本身幾乎不造成延遲，但若沒有 VAD，ASR 會持續推論，反而大幅增加整體系統的無效計算。

## VAD 的常見挑戰

### 1. False Positive（誤判噪音為語音）
背景噪音（如鍵盤聲、門聲）可能被誤判為語音，導致 ASR 接收到無意義輸入。

**解決方案**：提高 `threshold`（如 0.6–0.7），或增加 `min_speech_duration_ms`（如 500ms）。

### 2. False Negative（漏判語音為靜音）
輕聲說話或語音開頭的氣音可能被漏判，導致語句被截斷。

**解決方案**：降低 `threshold`，並在語音緩衝區前後各加一小段靜音邊界（padding）。

### 3. 說話停頓的處理
使用者在思考時可能有自然停頓，`min_silence_duration_ms` 太短會過早觸發 ASR，導致輸入被截斷。

**解決方案**：對話場景建議設為 300–500ms，讓使用者有思考空間。

### 4. 雙工（Duplex）場景的複雜性
在雙工系統中，虛擬病人說話時，使用者可能同時發話（打斷）。VAD 需要能夠偵測到使用者的插話（barge-in），並通知系統中斷 TTS 輸出。

## VAD 與醫療虛擬病人的特殊考量

在醫學訓練場景中，VAD 的設計需要考量以下特殊情況：

1. **醫學術語的停頓**：醫學生在思考診斷或回憶術語時，可能有較長的停頓，`min_silence_duration_ms` 應設定比一般對話更長（建議 500ms 以上）
2. **安靜的實驗室/診間環境**：醫學訓練環境通常較安靜，`threshold` 可以設定在標準值（0.5）
3. **多語言混用**：台灣醫學生可能中英文混用，Silero VAD 為語言無關，不受此影響

## 在 Cascade Pipeline 中的定位總結

VAD 是整個語音虛擬病人系統的「守門員」，它的核心價值在於：
- **效率**：只讓有意義的語音進入 ASR，避免靜音浪費計算資源
- **觸發控制**：提供明確的「說話開始/結束」訊號，讓 Pipeline 的觸發邏輯清晰可控
- **使用者體驗**：正確的 VAD 設定讓對話感覺自然流暢，錯誤的設定會讓使用者感到被打斷或需要等待

在延遲預算中，VAD 幾乎是「免費的」，但它的存在對整個系統的穩定性和資源效率至關重要。
