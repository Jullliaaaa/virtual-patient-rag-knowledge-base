# Cascade Speech Pipeline for Voice-Enabled Virtual Patients

## 什麼是 Cascade 語音系統？

Cascade 語音系統是一種將多個獨立的語音處理模組「串聯」起來的架構。每個模組各自負責一個子任務，並將輸出傳遞給下一個模組。相對於 End-to-End（端對端）系統，Cascade 架構的每個元件可以獨立訓練、替換與優化，具有更高的模組化彈性。

## 本系統的 Cascade 架構

本虛擬病人系統採用以下四階段 Cascade Pipeline：

```
使用者語音輸入
      ↓
[SER] 語音情緒辨識
  → 偵測使用者（醫學生）的情緒狀態（緊張、冷靜、困惑等）
      ↓
[ASR] 自動語音辨識
  → 將語音轉為文字（使用者說了什麼）
      ↓
[LLM + RAG] 語言模型 + 知識檢索
  → 根據文字內容與情緒輸入，生成病人的回應文字
      ↓
[TTS] 文字轉語音
  → 將病人回應文字合成為語音輸出
```

## Cascade vs End-to-End 的比較

| 面向 | Cascade | End-to-End |
|---|---|---|
| 架構 | 多個獨立模組串接 | 單一模型直接處理 |
| 可解釋性 | 高（可逐步檢查每個模組的輸出）| 低 |
| 模組替換 | 容易（替換單一元件即可）| 困難 |
| 錯誤傳播 | 上游錯誤會影響下游 | 不存在中間錯誤 |
| 訓練資料需求 | 各模組獨立訓練 | 需要大量端對端配對資料 |
| 延遲 | 較高（多次推論）| 通常較低 |

## Cascade 架構的主要挑戰

### 1. 錯誤傳播（Error Propagation）
ASR 產生的辨識錯誤會直接傳入 LLM，導致語言模型收到錯誤的文字輸入。例如：使用者說「胸口痛」，ASR 誤辨識為「胸口堂」，LLM 就可能產生不相關的回應。

### 2. 延遲累積（Latency Accumulation）
每個模組都有推論時間，四個模組串接後的總延遲可能影響對話的流暢性與使用者體驗。

### 3. 情緒資訊的整合
SER 輸出的情緒標籤需要有效地傳遞給 LLM，影響病人角色的回應風格。如何將非語言資訊（情緒）整合進語言生成仍是研究重點。

## 為什麼選擇 Cascade 而非 End-to-End？

對於虛擬病人應用場景，Cascade 架構具備以下優勢：

1. **可控性**：每個模組的輸出可以被監控，便於除錯與品質保證
2. **靈活替換**：可針對中文醫療語境替換更合適的 ASR 或 TTS 模型
3. **知識注入**：RAG 模組可以將醫療知識庫整合進對話生成，而不需重新訓練整個系統
4. **開發成本**：各模組可使用成熟的預訓練模型（Whisper、XTTS 等），大幅降低訓練成本
